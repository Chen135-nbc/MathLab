# P2 自定义知识点与 Mind Map

## 知识整理

在 Math Notes 点击小节名称，可进入小节自由整理页。页面提供「新建知识点」、知识点顺序调整及独立的小节笔记。小节笔记复用 Markdown、多语言资料和 LaTeX 助手。知识点可以先只有名称，正文保持为空。

进入知识卡后，在「管理知识点」修改名称、说明或所属小节。移动、改名、归档均保留原 ID、正文、模型和导图关联。使用小节列表的上下箭头排序，排序会直接保存。归档项从主目录隐藏，但仍在所属小节及名称搜索结果中，可恢复归档。删除前需确认，且先处理未保存笔记；知识卡采用逻辑删除，数据库保留已保存笔记和旧关联，未提供物理清理功能。已删除卡的旧导图仍可编辑和解除关联，不会删除导图或模型。

教材 JSON 继续提供册次、章节和小节。它的旧知识点数组作为历史数据保留，P2 初始化不再导入或覆盖这些条目；旧库已有的五个 ID 和个人笔记继续保留。新安装没有系统强制的知识点。当前只有第一章的三个小节，其他小节需要对照教材补齐，本轮没有猜测目录。

## Mind Map 工作台

主导航和首页均有独立入口，可以不关联任何课程新建导图。

- 修改导图名称、说明和可选的小节关联。
- 使用按钮添加子节点、同级节点。节点标题可用 $...$ 表示数学公式，右侧编辑备注和颜色标记。
- 拖动节点改变位置；通过右侧「调整父子层级」更换父节点，通过「同级上移/下移」调整分支顺序。
- 点节点上的加减按钮折叠或展开分支；删除非根节点时明确确认删除该分支，关联知识卡保留。
- 画布空白处拖动平移，滚轮缩放，左下角有放大、缩小和适应画布；「自动布局」恢复单侧树状排列。
- 画布聚焦时 Tab 添加子节点，Enter 添加同级，Delete 删除分支，Cmd/Ctrl-Z 撤销，Cmd/Ctrl-Shift-Z 或 Ctrl-Y 重做。输入框内使用普通文本快捷键。
- 手动「保存导图」保存全部节点、关联、备注、位置和视图。未保存离开会提示。撤销记录最多 50 步，仅保存在当前页面；成功保存后建立新基线并清空撤销记录。
- 导图库可打开、复制和确认删除。复制得到新的导图 ID 和节点 ID，保留对知识卡的引用。删除导图只级联删除该图的关联记录，不删除知识卡。

## 双向知识卡关联

选中节点后，可按小节或关键词搜索已有知识卡，点击关联后保存导图。普通节点可以不关联知识卡。单节点可关联一张知识卡，同一知识卡可被多个节点或多个导图引用。

「将节点整理为新知识点」要求导图已保存且没有未保存改动；选择所属小节，节点标题成为默认卡名。备注只有在明确勾选后才复制到新笔记；不会覆盖任何已有卡。创建与关联在一次数据库事务内完成，原节点继续保留。

知识卡的「关联思维导图」显示图名与节点名，入口带稳定节点 ID，打开时选中并居中该节点。必要时展开祖先分支；展开及视口调整属于当前视图草稿，保存后保留。节点重命名与知识卡移动不影响关联。解除关联并保存，不删除任何一端。

## 导入与导出

内部使用 MathLab 自有 JSON V1：

```json
{
  "format": "mathlab-mindmap",
  "version": 1,
  "title": "示例",
  "description": "",
  "section_id": null,
  "layout": "right",
  "viewport": { "x": 50, "y": 230, "zoom": 1 },
  "nodes": [{
    "id": "example-root",
    "parent_id": null,
    "title": "中心 $x^2$",
    "notes": "",
    "color": "navy",
    "collapsed": false,
    "position": null,
    "point_id": null
  }],
  "revision": null
}
```

JSON 导出当前草稿的完整结构，Markdown 导出节点标题的层级大纲。Markdown 不包含备注、颜色、视图及知识卡关联；完整备份请用 JSON。两个导出操作不修改数据库。

导入接受上述 JSON，或只包含 Markdown 标题与嵌套列表的大纲。输入限 1 MB、300 个节点、24 层父子边；Markdown 预留一个合成根节点，最多接受 299 个大纲条目。标题最多 120 字符，备注最多 4000 字符。图片、普通正文、混入额外块的列表项会提示整理后重试，不尝试图片识别。Markdown 内的中文与 LaTeX 原样保留。

导入保存为新图，并重新生成所有节点 ID。JSON 的知识卡引用继续指向本机已有 ID；缺失或已删除的卡、小节引用会拒绝导入并提示，不会通过标题猜测。跨项目文件可先把相关 point_id 和 section_id 设为 null。NotebookLM 只通过结构化 Markdown 大纲兼容；PNG、XMind 和 NotebookLM API 不在本轮范围。

## 技术选择

评估了 Mind Elixir 与 React Flow。Mind Elixir 自带传统思维导图交互；本轮选择 [React Flow](https://github.com/xyflow/xyflow) 12.12.1（MIT），因为已有应用是 React/TypeScript，且[自定义节点](https://reactflow.dev/examples/nodes/custom-node)可直接复用项目 KaTeX 与知识卡操作。树布局、节点编辑规则、撤销记录和自有数据格式在独立组件目录实现，React Flow 仅作为画布渲染与交互层。

新增运行依赖为 @xyflow/react。已有的 unified 与 remark-parse 声明为直接依赖，用于解析 Markdown AST；未另引入布局引擎或后端依赖。

## 数据升级与备份

版本 3 为增量升级，只新建 knowledge_meta、section_notes、mind_maps 和 mind_map_links，不改旧表字段或实体 ID。

首次启动升级前，使用 SQLite backup API 将整个旧库备份至同目录的 backups/pre-p2-时间.sqlite3，并检查完整性。已有知识点补充管理元数据；其创建时间从本次迁移开始记录，不推测历史创建时间。课程初始化从此只同步教材目录。迁移版本完成后不重复生成备份。

本轮开发已事先备份原库，并在临时副本执行两次升级，核对旧知识点、笔记、多语言档案、学习状态与模型表内容一致。可复查：

```bash
.venv/bin/python -m scripts.check_p2_upgrade
```

它只升级临时副本，不改原库。恢复时先停止服务，另存当前库，再把所需备份复制回数据库路径；不要将升级后的代码与恢复后的旧库同时运行并期待旧结构不变。备份和运行数据库均被 Git 忽略。

## 测试与实际范围

```bash
.venv/bin/python -m pytest backend/tests -q
npm --prefix frontend test
npm --prefix frontend run build
```

覆盖知识点创建、改名、排序、移动、归档和逻辑删除；旧库升级备份、课程重载不覆盖用户修改；小节笔记；导图保存、复制、关联、新建知识卡、解除与删除；无效树、循环、深度、缺失引用、JSON 和 Markdown 往返；主编辑操作的撤销重做。导图保存有 revision 检查，旧页面提交会返回 409，用户可以先导出当前草稿，重新打开后整合。

本轮限制为单侧树状布局和手动保存，尚未实现 PNG 导出、XMind、跨项目自动映射、回收站界面或完整富文本节点。浏览器控制连接不可用，原生浏览器检测到用户操作后停止接管；未将完整鼠标拖拽、文件选择器与快捷键的端到端链路计为已通过测试。
